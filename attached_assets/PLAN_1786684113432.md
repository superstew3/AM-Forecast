## Second: the cut-off. Do this before anything else.

`2025-12-31`, set by `pytest-admin` today, is test residue. It is also the most
consequential thing in the database — the cut-off decides which months count as
closed, so it moves every actual, forecast and budget figure in the system. A
cut-off in December 2025 means nothing after that date is ever treated as
complete.

Set it deliberately, through the API so it is audited:

```bash
# Whatever the last genuinely complete month is. NOT a month still transacting.
curl -X POST "$APP_URL/api/settings/cut-off" \
  -H 'Content-Type: application/json' \
  -d '{"cut_off_date":"2026-07-31","reason":"corrected after test residue"}'
```

Or directly, if the API is not running:

```sql
UPDATE reporting_settings
SET cut_off_date = DATE '2026-07-31', cut_off_set_by = 'sam:corrected'
WHERE id = 1;
```

**Confirm the date with Sam before running it.** It must be the end of the last
month that is genuinely complete in the data.

### Why it leaked, and the fix

Several fixtures move the cut-off so a rule can be tested on a dataset that
would not otherwise exercise it, and each restores it afterwards. That works
until a run goes wrong: a fixture that fails after its `UPDATE` but before its
`yield` never reaches its own restore, and the change is already committed. Your
run had seventeen fixture errors.

The attached `conftest.py` adds a session-level guard that snapshots
`reporting_settings` before anything runs and writes it back at the end whatever
happened in between, printing a line when it has to. Verified: a deliberately
leaking test now prints

```
[conftest] reporting_settings restored to 2026-07-31 — a fixture left it changed.
```

and the value is correct afterwards.

**Do not accept it.** Two reasons:

1. It was staged nine days ago by the 0015 import service, so its staging rows

   old-basis figures across the boundary.
2. Its file may be stale relative to what you would upload today anyway.

Reject it, and re-upload after the migration:

```sql

WHERE id = 2 AND status = 'pending';

```
